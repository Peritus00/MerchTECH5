# Fix Google OAuth "Error 400: invalid_request" on iOS

## Problem
Getting "Access blocked: Authorization Error" with "Error 400: invalid_request" on iPhone after updating the app.

## Root Cause
iOS requires its own OAuth Client ID configured with the correct Bundle ID. The Android Client ID won't work properly for iOS.

## Solution

### Step 1: Verify iOS Client Configuration in Google Cloud Console

1. **Go to Google Cloud Console**
   - Visit: https://console.cloud.google.com/
   - Select project: **MERTRADER APP**

2. **Navigate to Clients**
   - Go to **Google Auth Platform** → **Clients**
   - Find **"iOS client 1"** (Client ID: `587879962618-blge4b7msal6lokld99n82hl9f9tpifs...`)

3. **Edit iOS Client**
   - Click the **Edit** icon (pencil) next to "iOS client 1"
   - Verify:
     - **Bundle ID**: `com.peritus00.merchtech` ✅ (must match app.json)
   - Click **SAVE**

### Step 2: Verify OAuth Consent Screen

1. **Go to OAuth Consent Screen**
   - Navigate to **Google Auth Platform** → **Audience** (or **APIs & Services** → **OAuth consent screen**)

2. **Verify Configuration**
   - **Publishing status**: Should be "In production" ✅
   - **User type**: Should be "External" ✅
   - **Scopes**: Should include:
     - `openid`
     - `https://www.googleapis.com/auth/userinfo.profile`
     - `https://www.googleapis.com/auth/userinfo.email`

### Step 3: Update eas.json to Use iOS Client ID for iOS Builds

Since EAS doesn't support platform-specific env vars in the same profile, we have two options:

**Option A: Use iOS Client ID for All Builds (Recommended)**
- Update `eas.json` to use iOS Client ID
- iOS Client ID should work for both iOS and Android since they share the same bundle/package name

**Option B: Create Separate Build Profiles**
- Create separate profiles for iOS and Android with different Client IDs

### Step 4: Rebuild iOS App

After updating the configuration:

```bash
eas build --platform ios --profile preview
```

Or for production:

```bash
eas build --platform ios --profile production
```

### Step 5: Verify Redirect URI

The iOS app uses a custom URL scheme for OAuth redirects:
- **Scheme**: `merchtechapp` (from app.json)
- **Path**: `auth/google`
- **Full redirect URI**: `merchtechapp://auth/google`

This should be automatically handled by `expo-auth-session`, but verify it matches what's configured in your OAuth client.

## Troubleshooting

### Issue: Still getting "Error 400: invalid_request"
- **Solution**: Wait 5-10 minutes for Google's changes to propagate
- **Solution**: Verify the Bundle ID in iOS client matches exactly: `com.peritus00.merchtech`
- **Solution**: Check that OAuth consent screen is "In production" and scopes are added

### Issue: "App not verified" warning
- **Solution**: This is normal for apps in production. Users can still sign in, they'll just see a warning
- **Solution**: To remove warning, complete Google's app verification process (can take several days)

### Issue: Redirect URI mismatch
- **Solution**: For iOS, the redirect URI is automatically generated by `expo-auth-session` using the scheme from app.json
- **Solution**: Verify `app.json` has `"scheme": "merchtechapp"` configured
